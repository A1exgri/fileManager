# 📸 Image Hosting

Веб-приложение для хостинга, загрузки и управления изображениями с поддержкой базы данных PostgreSQL. Проект полностью контейнеризирован с помощью Docker, настроен для работы за прокси-сервером Nginx и поддерживает режим «горячей» перезагрузки при разработке.

---

## 🛠 Технологический стек

*   **Бэкенд:** Python (скрипт `main.py`, модули обработки в `app/`)
*   **База данных:** PostgreSQL
*   **Фронтенд:** HTML5, CSS3 (Bootstrap), JavaScript
*   **Оркестрация и деплой:** Docker, Docker Compose, Nginx

## ⚙️ Настройка окружения (`.env`)

Перед запуском проекта создайте файл `.env` в корневой директории и добавьте в него параметры конфигурации:

```env
# Пути к директориям
STATIC_DIR=static
MEDIA_DIR=images
LOG_DIR=logs

# Настройки отладки и логирования
DEBUG=True
LOG_LEVEL=10

# Настройки подключения к PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_HOST=db
POSTGRES_PORT=5432
POSTGRES_DB=postgres

# Ограничения приложения
IMAGES_LIMIT=5
```

## 🚀 Установка и запуск

Вы можете запустить проект в режиме разработки через Docker Compose со встроенным отслеживанием изменений или развернуть его локально.

### Вариант 1: Запуск в режиме разработки (Docker Compose + Watch)

Рекомендуемый способ для разработки. Контейнеры запускаются в фоновом режиме, а встроенный механизм `docker compose watch` налету синхронизирует код приложения с контейнером и автоматически перезапускает процесс при сохранении файлов.

Убедитесь, что у вас установлены **Docker** и **Docker Compose v2.22.0+**.

1. Клонируйте репозиторий и перейдите в папку проекта.
2. Создайте и заполните файл `.env` в корневой директории.
3. Запустите сборку и режим отслеживания:
   ```bash
   docker compose up -d && docker compose watch
   ```

#### 🔄 Как работает Docker Watch в проекте:
В соответствии с конфигурацией `docker-compose.yml`:
*   **Синхронизация:** Изменения в корневой директории автоматически попадают в контейнер по пути `/app`.
*   **Действие (`sync+restart`):** После синхронизации файлов контейнер автоматически перезапускается, обновляя бэкенд.
*   **Игнорирование:** Механизм `watch` полностью игнорирует папки `logs/`, `images/` и директорию `.git/`, что предотвращает циклические перезапуски от логов и загружаемых картинок.

### Вариант 2: Локальный запуск (Без Docker)

1. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv venv
   source venv/bin/activate  # Для Windows: venv\Scripts\activate
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создайте файл `.env` локально (для локального запуска измените хост базы данных на `POSTGRES_HOST=localhost`).
4. Запустите приложение:
   ```bash
   python main.py
   ```

## 🌐 Эндпоинты и маршрутизация (API & Роутинг)

В проекте реализованы следующие веб-страницы и API-эндпоинты:

### 📄 Веб-страницы (UI)

* **`GET /`** — Главная страница приложения (`index.html`).
* **`GET /upload`** — Страница для загрузки новых изображений (`upload.html`).
* **`GET /images*`** — Страница для просмотра галереи изображений (`images.html`).

### ⚙️ API Эндпоинты

#### `GET /api/images-data`
Получение списка данных об изображениях с поддержкой пагинации.
* **Параметры запроса:**
  * `page` (number, необязательный) — Номер страницы для фильтрации данных. Пример: `/api/images-data?page=2`. Если параметр не передан, по умолчанию открывается страница `1`.
* **Формат ответа:** JSON со списком объектов (метаданные изображений).

#### `GET /api/images`
Получение списка системных имен всех доступных изображений.
* **Формат ответа:** JSON (массив строк/имен файлов).

### ❌ Обработка ошибок
* Любой другой неуказанный путь вернет страницу **404 Not Found**.

## 💾 Резервное копирование (Бэкапы базы данных)

В проект интегрирован автоматический менеджер бэкапов на базе образа `postgres-backup-local`.

### 📅 Расписание и ротация
* **Автостарт:** Бэкап создается автоматически при каждом запуске контейнеров (`BACKUP_ON_START: "TRUE"`).
* **Периодичность:** Каждый день в полночь (`@daily`).
* **Хранение архивных копий:**
  * Ежедневные: последние **7 дней**
  * Еженедельные: последние **4 недели**
  * Ежемесячные: последние **6 месяцев**

### 📂 Где хранятся файлы?
Все резервные копии сохраняются на хост-машину в папку **`./pg_backups`** относительно корня проекта. Файлы упакованы в архивы вида: `db_name-YYYYMMDD-HHMMSS.sql.gz`.

### 🛠️ Управление бэкапами через CLI

#### Создать бэкап вручную прямо сейчас:
Если проект запущен, выполните команду для мгновенного создания копии:
```bash
docker compose exec pgbackups backup
```

#### Посмотреть логи бэкап-менеджера:
Проверить статус последнего копирования или ошибки авторизации:
```bash
docker compose logs pgbackups
```

#### Восстановление базы данных из бэкапа:
Для восстановления структуры и данных выполните следующую команду (замените `имя_файла.sql.gz` на ваш реальный архив):
```bash
docker compose exec -T db gunzip -c /backups/имя_файла.sql.gz | docker compose exec -T db psql -U postgres -d postgres
```
