# 📸 Image Hosting

Веб-приложение для хостинга, загрузки и управления изображениями с поддержкой базы данных PostgreSQL. Проект полностью контейнеризирован с помощью Docker, настроен для работы за прокси-сервером Nginx и поддерживает режим «горячей» перезагрузки при разработке.

---

## 🛠 Технологический стек

*   **Бэкенд:** Python (скрипт `main.py`, модули обработки в `app/`)
*   **База данных:** PostgreSQL
*   **Фронтенд:** HTML5, CSS3 (Bootstrap), JavaScript
*   **Оркестрация и деплой:** Docker, Docker Compose, Nginx

## ⚙️ Настройка окружения (`.env`)

Перед запуском проекта создайте файл `.env` в корневой директории и добавьте в него параметры конфигурации:

```env
# Пути к директориям
STATIC_DIR=static
MEDIA_DIR=images
LOG_DIR=logs

# Настройки отладки и логирования
DEBUG=True
LOG_LEVEL=10

# Настройки подключения к PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_HOST=db
POSTGRES_PORT=5432
POSTGRES_DB=postgres

# Ограничения приложения
IMAGES_LIMIT=5
```

## 🚀 Установка и запуск

Вы можете запустить проект в режиме разработки через Docker Compose со встроенным отслеживанием изменений или развернуть его локально.

### Вариант 1: Запуск в режиме разработки (Docker Compose + Watch)

Рекомендуемый способ для разработки. Контейнеры запускаются в фоновом режиме, а встроенный механизм `docker compose watch` налету синхронизирует код приложения с контейнером и автоматически перезапускает процесс при сохранении файлов.

Убедитесь, что у вас установлены **Docker** и **Docker Compose v2.22.0+**.

1. Клонируйте репозиторий и перейдите в папку проекта.
2. Создайте и заполните файл `.env` в корневой директории.
3. Запустите сборку и режим отслеживания:
   ```bash
   docker compose up -d && docker compose watch
   ```

#### 🔄 Как работает Docker Watch в проекте:
В соответствии с конфигурацией `docker-compose.yml`:
*   **Синхронизация:** Изменения в корневой директории автоматически попадают в контейнер по пути `/app`.
*   **Действие (`sync+restart`):** После синхронизации файлов контейнер автоматически перезапускается, обновляя бэкенд.
*   **Игнорирование:** Механизм `watch` полностью игнорирует папки `logs/`, `images/` и директорию `.git/`, что предотвращает циклические перезапуски от логов и загружаемых картинок.

### Вариант 2: Локальный запуск (Без Docker)

1. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv venv
   source venv/bin/activate  # Для Windows: venv\Scripts\activate
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создайте файл `.env` локально (для локального запуска измените хост базы данных на `POSTGRES_HOST=localhost`).
4. Запустите приложение:
   ```bash
   python main.py
   ```
